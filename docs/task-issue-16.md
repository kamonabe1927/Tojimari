- 依頼: issue #16「[自走] 外部コマンド由来の文字列の制御文字を、表と標準エラー出力でそのまま端末に出さない」。週の計画（#17、2026-11-21）で PM が立てた issue
- 書いた人: PM
- 関連: [output-1.1.md](output-1.1.md) の 1.3（終了コード 1 のときの理由を標準エラー出力に出す）と 3.2〜3.5（人が読む表の決まり）、[design-issue-5.md](design-issue-5.md) の 5.4（想定外の例外）、[task-issue-15.md](task-issue-15.md)（`CommandError` と理由の文言）

## 1. 範囲の判断

マニフェストと今の段階の中に収まると判断した。

- 種類は「Tojimari 自身のセキュリティ（危ない書き方）」で、`docs/agent-rules.md` の 6 の週の計画の条件に当たる。根拠は issue に書かれた `docs/vision.md` の 3（1.1 の完了の目安）と、`docs/spec-1.1.md` の 4・6 が出力の決定を置いた [output-1.1.md](output-1.1.md) の 1.3 と 3.2
- 変えるのは見せ方だけ。JSON の中身、文言、終了コード、表の列と並びは変えない
- 新しい依存は入れない（標準ライブラリだけで行う）。通信は起こさない
- 文書と出力に「安全になる」「防げる」と読める表現を書かない（`docs/manifest.md` の 3）。置き換えは「端末の表示が変わらないように見える形にする」とだけ書く

## 2. main を読み直した結果（issue の「#12 などが先にマージされたとき」）

issue を立てた後に #12〜#15 がマージされた（main は 17139df）。表に出る外部コマンド由来の値が増えている。

| 出るところ | 外部コマンド由来の値 |
|---|---|
| `[重点リスト]`（`tojimari/table.py` の `_focus_rows`） | 版、アーキ、入れた元。表の下の「動いているカーネル」 |
| `[後から入れたもの]`（`_user_installed_lines`） | パッケージ名、版、アーキ、入れた元 |
| `[古さ]`（`_staleness_lines`） | 重要度の名前、件数、日時などの値（dnf の出力とデータベースから来るもの） |
| 標準エラー出力（`tojimari/check.py` の `_rpm_failure_message` → `tojimari/cli.py`） | rpm の標準エラー出力の末尾（`CommandError.stderr_tail`、最大 5 行） |

- `[注意]` の文（`notices`）は Tojimari が組み立てた文で、`notices.command_reason` は標準エラー出力を入れない。ただし、表の値と同じ置き換えを `[注意]` の文にもかけてよい（Tojimari の文には制御文字が無いので見た目は変わらない）。どこにかけるかはテックリードが決める
- パッケージ名などの JSON の値は、`json.dumps` が制御文字を `\u001b` の形で出すので、JSON 側は変えない

## 3. 要件

### 3.1 置き換えの決まり

1. 対象の文字は、C0（U+0000〜U+001F。改行 `\n`、タブ `\t`、復帰 `\r` を含む）、DEL（U+007F）、C1（U+0080〜U+009F）とする
2. 対象の文字を、`\x` と 16 進の小文字 2 桁の形（例: ESC は `\x1b`、改行は `\x0a`）に置き換える。どの文字も 2 桁で表せる
3. 逆斜線 `\` そのものは置き換えない。表は確認の補助で、元の値は JSON にあるため。読み分けが要るときは JSON を見る、と `docs/output-1.1.md` に書く
4. 置き換えは表示の直前（表を組み立てるところと、標準エラー出力に書くところ）で行う。レポート（JSON にする辞書）の値は書き換えない
5. 対象外: Unicode の書式の文字（双方向の上書き U+202E など）と U+2028・U+2029 は、issue の範囲（C0、DEL、C1）に入らないので今回は置き換えない。`docs/output-1.1.md` に「置き換えるのは C0、DEL、C1 だけ」と書き、それ以外を置き換えないことを隠さない。足すかは、本人が別に頼むか、次の週の計画で考える

### 3.2 表

1. 表に出す外部コマンド由来の値（2 の表の 3 か所すべて）に 3.1 をかける
2. 列の幅は置き換えた後の文字列で数える。置き換えた形は ASCII だけなので、1 文字 1 桁になる。全角を 2 桁で数える今の決まり（`display_width`）は変えない
3. 表の改行は行の区切りだけになる（値の中の改行は `\x0a` になり、行を増やさない）
4. 値に制御文字が無いときの表の出力は、1 文字も変わらない

### 3.3 標準エラー出力

1. 終了コード 1 のときに出す理由のうち、rpm の標準エラー出力の末尾の各行に 3.1 をかける。行の区切りは今の `_tail`（`splitlines` で分けて `\n` でつなぐ）のままとし、区切りの `\n` だけを残す。`_tail` の分け方は変えない
2. 外部コマンド由来の 1 行に、長さの上限を付ける。上限の値、数え方、超えたときの表し方はテックリードが決め、`docs/output-1.1.md` に書く。次を満たすこと
   - 上限は置き換えた後の文字列にかけ、`\x1b` のような置き換えた形の途中で切らない
   - 切ったことが読む人に分かる印を付ける（印の文言は Tojimari の文として、「安全」と読める言葉を使わない）
   - Tojimari の文（`rpm の問い合わせが終了コード 1 で失敗しました` など）は短くも変えもしない
3. 5 行までという今の行数の上限は変えない
4. どの段（`runner`、`check`、`cli`）で置き換えと上限をかけるかはテックリードが決める。ただし `CommandError.stderr_tail` を JSON に出すことはしない（今も出していない）

### 3.4 置き換えの部品

- 置き換えと上限の関数は 1 か所に置き、表と標準エラー出力の両方から使う。置く場所（モジュール）はテックリードが決める

### 3.5 テストで確かめること

1. 置き換えの関数: C0 の各種（`\x00`、`\t`、`\n`、`\r`、`\x08`、`\x1b`）、DEL、C1（`\x9b` など）が `\x` と 2 桁になること。全角文字、ASCII の普通の文字、逆斜線はそのまま残ること
2. 表: 記録出力（`tests/recorded.py`）またはテストの中のレポートに、制御文字を含めた架空の値（パッケージ名、版、入れた元、動いているカーネルなど）を足し、`render_table` の出力に U+0000〜U+001F（行の区切りの `\n` を除く）、U+007F、U+0080〜U+009F が 1 つも無いこと。列が揃っていること（置き換えた値の行と、ほかの行の列の始まりが同じ桁）
3. JSON: 同じ入力で `tojimari check --json` の出力が `json.dumps` の結果のままで、値が書き換わっていないこと
4. 標準エラー出力: rpm の失敗を差し替えで起こし、`stderr_tail` に ESC、`\r`、バックスペースを含めたとき、`cli.main` が標準エラー出力に書く文字列に、行の区切りの `\n` 以外の制御文字が無いこと。上限を超える 1 行が、決めた印つきで切られること。Tojimari の文はそのままであること
5. 値に制御文字が無いときの表と標準エラー出力が、今と同じであること（今あるテストがそのまま通ることで確かめる）
6. rpm と dnf は実行しない（[design-issue-5.md](design-issue-5.md) の 6）。実機の生の情報をテスト用データに入れない（禁止事項 7）

### 3.6 文書

- `docs/output-1.1.md` の 3.2 に置き換えの決まり（3.1 の 1〜3・5 と、列の幅は置き換えた後で数えること）を足す
- 標準エラー出力の決まり（3.3 の 1・2 と、テックリードが決めた上限）は、issue のとおり 3.2 に書き、1.3 の「理由を標準エラー出力に出す」の下から 3.2 を指す 1 行を足す

## 4. やらないこと

- JSON の中身を変えない。レポートの値を書き換えない
- 文言、終了コード、表の列や並びを変えない
- 想定外の例外のトレースバックの扱い（[design-issue-5.md](design-issue-5.md) の 5.4）を変えない
- `runner._tail` の行の分け方と 5 行の上限を変えない
- 3.1 の 5 の Unicode の書式の文字などを置き換えない（範囲を広げない）
- 新しい依存を入れない
- 「安全になる」「防げる」と読める表現を文書や出力に書かない

## 5. 終わりの条件

- 表と標準エラー出力に、外部コマンド由来の生の制御文字（C0、DEL、C1）が出ない。改行は表の行の区切りと、rpm の末尾の行の区切りだけ
- 標準エラー出力の外部コマンド由来の 1 行に上限があり、その値と表し方が `docs/output-1.1.md` にある
- `tojimari check --json` の出力は変更の前と同じ（`generated_at` を除く）
- 置き換えの決まりが `docs/output-1.1.md` の 3.2 にある
- 3.5 のテストがあり、リポジトリの最上位で `python3 -m unittest` がすべて通る

## 6. 実機での確認

要らない。外部コマンドの出力に制御文字が入る場面は実機で起こしにくく、テストは記録出力と差し替えで行うため。

## 7. テックリードに伝えること

- 決めてほしいこと: 置き換えの関数を置くモジュール（3.4）、置き換えと上限をかける段（3.3 の 4）、標準エラー出力の 1 行の上限の値・数え方・切った印（3.3 の 2）、`[注意]` の文にも置き換えをかけるか（2）
- 気をつけてほしいこと: `display_width` は `east_asian_width` が `A`（曖昧）の文字も 2 桁で数える。置き換えた形は ASCII なので影響しないが、置き換える前の文字列で幅を数えないこと
- #15 の変更（`CommandError.timeout` と理由の文言）はそのまま使い、触らない
