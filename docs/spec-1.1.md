# 1.1 仕様: 入っているソフトと古さの確認（仮版）

- 作成日: 2026-11-20
- 状態: 1.1 の範囲で合意した内容のまとめ。決めた経緯と理由は [requirements.md](requirements.md) の「1.1 で決まったこと」を参照
- 位置付け: 第1段階（現状チェック）の最初の小段階。読み取りだけを行い、VM の設定は一切変更しない

## 1. 目的

脆弱性情報が出たときに、ソフトごとに確認コマンドを調べて打つ負担を減らす。
あわせて、放置して古くなっていないかを一目で分かるようにする。
Tojimari はセキュリティを担保しない。表示はあくまで確認の補助とする。

## 2. 表示するもの

### 2.1 後から入れたもの

- 判定方法: dnf 履歴の1番（OS インストール時の処理、`@anaconda`）に含まれたパッケージ名を OS 標準とみなし、`dnf repoquery --userinstalled` からそれを除いたものを「後から入れたもの」とする
- 表示する内容: パッケージ名、バージョン、入れた元のリポジトリ、今動いているかの印、systemd のサービスかの印
- 履歴が取れない場合: `from_repo` が `anaconda` かで代わりに判定し、精度が落ちることを表示する
- 履歴の 1 番の取り方: dnf の履歴のデータベース（`/var/lib/dnf/history.sqlite`）を読み取り専用で開いて読む（2026-11-21、issue #10・#12。詳しくは [task-issue-12.md](task-issue-12.md)）

### 2.2 重点リスト

後から入れたものの判定とは別枠で、入っていれば常に表示する。

| パッケージ | 選んだ理由 |
|---|---|
| kernel | 土台。動いている版と入っている版の両方を表示する |
| openssh-server、openssh | 外から届く入口 |
| openssl-libs | 多くのソフトが使う暗号ライブラリ（openssl コマンドではなくライブラリ本体） |
| glibc | ほぼすべてのソフトが使う土台 |
| sudo | 権限昇格につながる |
| systemd | 土台。権限の強い処理を担う |
| polkit | 権限昇格につながる |

- 表示する内容: 2.1 と同じ
- リストは Tojimari が固定で持つ。利用者による足し引きは、要望が出てから考える

### 2.3 古さ

1. セキュリティ更新の件数と重要度（`dnf updateinfo`）
   - リポジトリ情報が取得できなかったときは「確認できなかった」と表示し、「更新なし」とは表示しない
2. 再起動待ちかどうか（動いているカーネルが、入っている最新版より古くないか。`dnf needs-restarting -r` も使える）
3. 最後に更新した日（dnf 履歴の最後の update / upgrade）
- 取り方（2026-11-22、issue #13。詳しくは [task-issue-13.md](task-issue-13.md)）: 1 は `dnf repoquery --cacheonly --upgrades --security` を重要度ごとに `--queryformat` 付きで呼び、件数はセキュリティ更新が出ているパッケージの名前の数とする。通信を起こさないので、数は dnf が最後にリポジトリ情報を取得した時点のもので、その旨を出す。2 は rpm の記録の `kernel` の版を rpm の決まりで比べる（`dnf needs-restarting` は使わない）。3 は dnf の履歴のデータベースを読み取り専用で読み、版を上げる項目を含み最後まで終わった処理のうち最新のものの時刻を出す

### 2.4 今動いているかの印

- 今動いているプロセスの実行ファイルを `rpm -qf` でパッケージに紐づけ、2.1 と 2.2 の一覧に「今動いている」と印をつける
- systemd のサービスとして動いているかも印にする
- 取り方（2026-11-22、issue #14。詳しくは [task-issue-14.md](task-issue-14.md)）: `/proc/<pid>/exe` で実行ファイルのパスを取り、rpm の `--queryformat` 付きの問い合わせでパッケージの版に結びつける。サービスかどうかは `/proc/<pid>/cgroup` の cgroup v2 のパスで見分ける（最後が `.service` で、利用者のセッションや利用者ごとの systemd の下ではないもの）。Tojimari 自身と、違うマウントの名前空間（Docker コンテナの中など）のプロセスは結びつけない。権限で読めなかったプロセスの数を出す

## 3. 表示の注意（出力に必ず含める）

- 表示対象は、dnf（rpm）で入れたものと重点リストだけ。パッケージ管理の外で個別にビルド・配置したもの、pip などの言語ごとのパッケージ管理で入れたもの、Docker コンテナの中身は表示しない。表示されないことを「未インストール」と扱わない
- 「今動いている」はその瞬間の様子。印がないことを「使っていない」と扱わない
- root なしで実行したときは、見えた範囲だけを表示し、その旨を表示する
- 履歴が取れず代わりの判定を使ったときは、その旨を表示する

## 4. 実行と出力

- `sudo` で実行する前提とする
- 出力は標準出力のみ。人が読む表と JSON の両方を出せるようにする
- 外部への送信は行わない
- FastAPI の画面は 1.1 には含めない。1.1 のすぐ後に、この JSON を読んで表示する形で足す
