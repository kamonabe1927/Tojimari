- 作成日: 2026-11-21
- 依頼: issue #5「1.1: 重点リストのパッケージとバージョンを表示する（土台づくりを含む）」（本人が立てた依頼）
- 書いた人: PM
- 関連: [spec-1.1.md](spec-1.1.md)（1.1 の仕様）、[output-1.1.md](output-1.1.md)（今回決めたコマンド、JSON、表）

## 1. 範囲の判断

マニフェストと今の段階の中に収まると判断した。

- 1.1（入っているソフト、古さ）の中の、spec-1.1.md の 2.2「重点リスト」にあたる。段階を超えない
- 読み取りだけで、VM の設定を変えない。出力は標準出力だけで、外部へ送らない（マニフェストの 3）
- Python の標準ライブラリだけで書き、テストも標準の `unittest` を使う。新しい依存は入れない（禁止事項 5 の確認は要らない）
- 使う外部コマンドは、AlmaLinux に最初から入っている `rpm` と `dnf` だけ
- 許可リスト外の通信、調べ物は要らない

## 2. 今回のタスク

1 回の実行で終わる大きさとして、次をまとめて行う。

1. `tojimari check` の土台を作る（起動、引数、JSON と表の出し分け、表示の注意、終了コード）
2. 重点リスト（kernel、openssh-server、openssh、openssl-libs、glibc、sudo、systemd、polkit）の表示を作る
3. コマンドを実行する部分と、結果を読み取る部分を分け、読み取る部分を記録した出力で `unittest` から確かめる

今回やらないこと（issue のとおり）:

- 後から入れたものの判定、古さ、今動いているかの印（別の issue）。JSON にはこれらの置き場所を決めるだけで、空の値や仮の値を出さない
- FastAPI の画面
- VM の設定の変更

## 3. 要件

### 3.1 表示する内容

- 重点リストの各パッケージについて、rpm の記録にあれば、パッケージ名、バージョン（epoch、version、release）、アーキテクチャ、入れた元のリポジトリを表示する
- 同じ名前の版が複数あれば、すべて表示する
- kernel は、入っている版すべてと、今動いている版を表示し、どの入っている版が動いているかが分かるようにする
- rpm の記録にないものは「入っていない」と表示する。その意味は「rpm の記録にない」ことだけで、パッケージ管理の外は見ていないことが表示の注意から分かるようにする
- 入れた元のリポジトリが取れないときは、取れないことを表示し、ほかの表示は続ける（全体を失敗にしない）

### 3.2 出力

- 人が読む表と JSON を出し分けられる。形は [output-1.1.md](output-1.1.md) のとおり
- spec-1.1.md の「3. 表示の注意」を出力に含める。root なしで実行したときはその旨を出す
- Tojimari 自身は書き込みを一切しない（ファイル、ログ、キャッシュを作らない）。呼び出した dnf が自分のログ（`/var/log/dnf.log` など）に書くことはありうるが、これは dnf の通常の動きで、VM の設定は変えない

### 3.3 情報の取り方

- 読み取る出力は、`rpm --queryformat` や `dnf repoquery --queryformat` のように、Tojimari 側で形を決められるものだけを使う。実機の画面表示の形を推測して読み取らない
  - 例: 入っていないパッケージを `rpm -q <名前>` のメッセージで判定しない。`rpm -qa --queryformat ...` で形を決めた一覧を取り、名前で絞る
- 入れた元のリポジトリは dnf の記録（`from_repo`）から取る。rpm 自体はこれを持っていないため
  - 通信を起こさないよう、dnf はキャッシュだけを使う指定で呼ぶ（オフラインの VM でも重点リストが空にならないようにするため）。リポジトリ情報の取得が要る「古さ」は別の issue で扱う
  - dnf が警告などを標準エラー出力に出しても、標準出力だけを読む
- 今動いているカーネルは `os.uname().release` で取る（外部コマンドを増やさないため）
- 外部コマンドはシェルを通さず、引数の配列で呼ぶ。タイムアウトを付ける

### 3.4 動かす環境

- AlmaLinux 10.2 の標準の python3 で動くこと
- 作業する環境（クラウド実行環境）は Python 3.11 で、rpm と dnf がない。どちらでも動くよう、3.11 で使えない書き方をしない
- 起動は `sudo python3 -B -m tojimari check`（理由は output-1.1.md の 1.2）

### 3.5 テスト

- 標準の `unittest` だけを使い、リポジトリの最上位で `python3 -m unittest` を実行すれば全部通ること
- 読み取る部分は、記録した出力（テスト用データ）で確かめる。テスト用データは、output-1.1.md と 3.3 で決めた queryformat の形に沿って作る。実機の生の情報（ホスト名、ユーザー名、パスなど）を入れない
- 少なくとも次を確かめる
  - 重点リストが全部入っているとき、一部が入っていないとき
  - kernel が複数世代入っていて、そのうち 1 つが動いているとき。どれも動いている版と一致しないとき
  - epoch があるパッケージ、同じ名前で arch が違う版があるとき
  - dnf から入れた元が取れたとき、取れなかったとき（`from_repo_available` が false、該当の notice が出る）
  - root のときとそうでないとき（`not_root` の notice）
  - JSON の構造と項目名が output-1.1.md のとおりであること。表に JSON と同じ中身が出ること
  - rpm の問い合わせが失敗したとき、終了コード 1 になり、中途半端な JSON を出さないこと
- コマンドを実行する部分は、テストでは差し替えられるようにする（rpm、dnf、uname を実際に呼ばない）

## 4. 終わりの条件

- `python3 -m unittest` がすべて通る
- PR に、実機での確認の手順（5）がある

## 5. 実機での確認の手順（PR に書く内容の元）

本人が検証用 VM（AlmaLinux 10.2）のリポジトリの最上位で実行する。実装の結果に合わせて、セキュリティ担当が PR を作るときに整える。

| 手順 | コマンド | 正しいときの表示 |
|---|---|---|
| 1 | `sudo python3 -B -m tojimari check` | 重点リストの 8 件が表の順に並ぶ。入っているものは版と入れた元が出る。kernel のうち 1 行に `<- 動いている` が付き、表の下の「動いているカーネル」が `uname -r` と同じ。`[注意]` に表示対象と「今動いている」の注意が出て、root でない旨の注意は出ない |
| 2 | `rpm -q kernel openssh-server openssh openssl-libs glibc sudo systemd polkit` | 1 の表の版と一致する（入っていないものは rpm も入っていないと言う） |
| 3 | `uname -r` | 1 の「動いているカーネル」と一致する |
| 4 | `sudo python3 -B -m tojimari check --json \| python3 -m json.tool` | JSON として読める。`format` が `tojimari-check`、`schema_version` が 1、`run.is_root` が true。中身が 1 の表と同じ |
| 5 | `python3 -B -m tojimari check`（sudo なし） | 表は出る。`[注意]` に root なしで実行した旨が出る |
| 6 | `dnf repoquery --installed --cacheonly --queryformat '%{name} %{from_repo}' kernel openssh-server` など、実装が使う dnf の呼び方そのもの | 1 の「入れた元」と一致する |
| 7 | `git status` | 実行のあとに、リポジトリに新しいファイル（`__pycache__` など）ができていない |

- 6 の dnf の呼び方は、実装で決まったものに置き換える
- 実機の出力を issue や PR に貼るときは、ホスト名などを置き換えてから貼る（禁止事項 7）

## 6. テックリードへの申し送り

- ファイルとモジュールの分け方、関数の分担、エラーと権限不足のときの振る舞いの細部は、テックリードが決めて `docs/` に書く
- JSON の項目名と構造、表の見た目、コマンド名と起動、終了コード、表示の注意は [output-1.1.md](output-1.1.md) で決めた。変える必要があれば、設計に進む前に PM への差し戻しとして返す
- 後で足す「後から入れたもの」「古さ」「今動いているかの印」が乗る形にしておく（2.3 の版の要素を共通にする、`checks` の下にキーを足せる、など）。ただし今回はそれらの中身を作らない
- `rpm --queryformat` の epoch の扱い（epoch が無いときの出し方）や、`dnf repoquery` のキャッシュだけを使う指定と `%{from_repo}` は、手元で確かめられない。条件式などで Tojimari 側が形を決められる書き方を選び、確かめきれない点は実機確認の手順（5）に入れる
- `dnf repoquery` の呼び出しが失敗したとき（キャッシュが無いなど）は、入れた元を null にして続ける。`rpm` の呼び出しが失敗したときだけ全体を失敗（終了コード 1）にする
