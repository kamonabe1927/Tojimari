# Tojimari（戸締まり）

個人用のローカル開発VMでも、戸締まりはする。

> 状態: 構想段階の仮版です。内容はこれから変わります。

## これは何か

個人で使う開発用VM（AlmaLinux）を、手間をかけずに「固い状態」から始められるようにするOSSです。

用途ごとにVMを使い分けたいとき、毎回のキッティングが面倒で
「どうせ個人用だし、デフォルトのゆるい設定でいいか」となりがちです。
Tojimari は、その面倒をなくすことで、ゆるいままが既定値になるのを防ぎます。

商用環境は費用をかけて守られることが多い一方、開発環境は使い捨ての感覚で扱われ、
堅牢でないままになりがちです。Tojimari は、開発環境を少しでも守れる土台を作ることを目指します。

## これは何でないか

Tojimari はセキュリティソフトではありません。セキュリティ面の環境準備を補助するものであり、
セキュリティを担保するものではありません。

## 対象

- 用途: 開発環境（商用環境は対象外）
- OS: AlmaLinux
- 環境: UTM、VMware Player などで起動するローカルの仮想マシン
- 利用者: 個人（自分ひとり）

## 対象外

- 商用環境
- VPS やクラウドなど、外部に公開されるサーバ
- AlmaLinux 以外のディストリビューション
- 複数人での共用環境
- メールや Slack など外部への通知・送信（結果はログ、標準出力、画面で確認します）

## 考え方（たたき台）

「あるべき状態」の定義を1つ持ち、そこから次の3つを出します。

- 適用: 素の AlmaLinux に当てて、あるべき状態にする
- 診断: 適用せずに、あるべき状態とのズレだけを見る
- 監視: いつもと違うことだけをログに記録する

## リリースの進め方

一度に全てを出さず、次の順で段階的にリリースします。

1. 現状をチェックできる
2. 現状とあるべき状態の差分を抽出できる
3. 差分を反映できる

詳しくは [docs/requirements.md](docs/requirements.md) を参照してください。
